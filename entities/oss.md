# 阿里云 OSS

对象存储服务，提供海量、安全、低成本、高可靠的云端存储能力。

## 核心优势

### 1. 无限扩容

存储容量无上限，不论几 MB 还是几 EB，即买即用，无需提前规划。

### 2. 降低成本

| 维度 | 传统存储 | OSS |
|------|---------|-----|
| 存储介质 | RAID 阵列（硬件成本高） | 多副本冗余（软件实现） |
| 分级存储 | 不支持 | 标准/低频/归档/冷归档，成本降数倍 |
| 带宽 | 服务器带宽贵 | CDN 加速，按量计费 |

### 3. 极高可靠性

- 数据持久性：99.9999999999%（12 个 9）
- 多副本冗余：自动跨多设备、多可用区备份
- 安全防护：防盗链、DDoS 防护、服务端加密、RAM 策略

## 与 CAP 定理

OSS 作为分布式系统，遵循 [[cap-theorem]]。在分区容错（P）必然存在的前提下，OSS 选择了：

- **可用性（A）优先**：网络故障时仍能保证节点响应
- **最终一致性**：写入后短暂延迟，所有副本最终同步

## 在湖仓架构中的角色

OSS 是 [[lakehouse]] 架构的存储底座：

```
OSS（对象存储）  →  [[iceberg]] / [[delta-lake]]（表格式）  →  [[duckdb]] / [[polars]]（计算）
  廉价、无限扩展           元数据管理、ACID 事务                    按需启动、弹性计算
```

**对象存储 vs 文件存储的碾压性优势**：
- 成本低一到两个数量级
- 无限弹性扩展
- 原生多副本容灾
- 无需运维存储集群

**短板**：
- 单次请求延迟高于本地磁盘
- 目录列举（ListObjects）在海量文件下性能退化

但 OLAP 恰恰对延迟不敏感 — 用户提交查询后等待数秒到数分钟是可接受的。
