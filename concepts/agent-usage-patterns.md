# Agent 使用模式

决定 Agent 质量上限的不是模型能力，是使用方式。

## 核心逻辑

AI 没有主动的"质量意识"。没有反馈 = 没有信号说"这里不对"。长期不纠正不会导致崩溃，但会停在"能用但差一点"的层次。

纠正的本质不是"告诉 AI 哪里错了"，而是建立共同的判断标准。memory 机制将偏好固化成持久规则，同类场景不用再重复纠正。

## 交互模式

### 主动驾驶 vs 被动接受

- **被动使用**：AI 做了什么就接受什么，积累不满但不说
- **主动驾驶**：每次交互都是一次校准，频繁检查产出，不一致的立即纠正

### 要求解释动机

当 AI 做了超出预期的操作时，直接问"为什么这样做"。低成本的自检机制。

### 问"为什么不用另一个方案"

比直接否定更有效——直接否定让 AI 防御性辩护，提问让它主动审视。

## 指令技巧

### 负面指令优于正面指令

"不要自动提交"比"提交时先通知我"效果好得多。

正面指令是路径，覆盖已知场景。负面指令是围栏，覆盖所有未预想的路径。

### 先观察再行动

改代码之前让 AI 先读相关文件、解释现有结构。带着理解去改，比带着假设去改错误率低一个数量级。

### 一次只做一件事

上下文窗口是有限资源。多任务并行会互相挤占上下文，AI 开始丢前面的约束。

### 修改前列出计划

"先说你要改哪些文件、改什么，我确认后再动手"。成本极低，但能拦截大量越权行为。

## 审查习惯

### 看 diff，不看全文

diff 是 AI 实际做了什么的最短表达。

### 纠正要写入持久化

口头纠正只影响当前会话。写入 memory 或 skill 的纠正才具有复利效应。

**记忆策略三原则**：
- **存事实**：`User prefers X`（陈述句，客观描述）
- **不存指令**：`Always do X`（系统提示词已包含行为准则）
- **不存临时态**：会话进度、PR 编号（靠 session_search 检索）
