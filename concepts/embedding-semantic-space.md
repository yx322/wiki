# Embedding 与语义空间映射

Embedding 的作用：把高维原始空间映射到一个**距离重新变得有意义的低维语义空间**——这也是为什么向量检索总是先做 embedding 再算距离。

## 1. 为什么原始空间里距离没有意义

检索的对象是文本（如商品名"安全防护帽"和用户查询"推荐安全帽"）。文本没法直接算距离——计算机能算距离的只有数字。简单的数字化方式全部丢失语义：

| 数字化方式 | 结果 |
|-----------|------|
| 字典序编码（字→编号） | "帽"=5802，"盔"=1043，距离任意 |
| one-hot（词表维度） | 维度 = 词表大小（几万维），任何两个词都正交，**距离全是 √2，人人等距** |
| 关键词匹配 | "安全帽"和"安全防护帽"字面不重合 → 距离最大，但语义上最近 |

问题不在"高维"本身，在于这些坐标系的**轴没有语义结构**：one-hot 里"安全"和"防护"两个轴互相完全无关，而它们在真实语义里强相关。距离算在这种坐标系上，等于用一把刻度乱了的尺子量东西。

## 2. Embedding 做了什么：学一个新坐标系

Embedding 模型（如 text-embedding-v4，输出 1024 维）是一个训练出来的函数：

```
f(文本) → ℝ¹⁰²⁴
```

训练目标就是**让语义接近的文本，输出向量也接近**（对比学习：拉近正样本对、推远负样本对）。训练完成后，这 1024 个维度不再是任意的字/词编号，而成了某种"语义特征方向"——模型自己学出来的，人未必能说清某一维具体代表什么，但整个坐标系有语义结构。

关键点：**压缩不是目的，重排才是**。1024 维相对几万维的词表确实"低"了，但真正的变化是：原始空间里"距离"这个概念不存在/无意义，新空间里距离被重新定义为"语义相似度"。

```
原始空间：   "安全防护帽" ──距离√2── "安全帽"     （正交，无关）
                 ↓ embedding
语义空间：   cos("安全防护帽", "安全帽") ≈ 0.9   （相邻）
             cos("安全帽", "夏天")       ≈ 0.1   （远离）
```

## 3. 为什么向量检索"先 embedding 再算距离"是必然流程

因为距离只在那个语义空间里有定义：

```
查询"推荐安全帽" ──f()──▶ q向量 ─┐
                                 ├─ 余弦距离 ──▶ 最近的 K 个 = 语义最相关的 K 条
商品库每条 ──f()──▶ 向量库       ─┘
```

两个必要推论：

1. **两边必须用同一个模型**——不同模型的坐标系完全不同（见 [[embedding-migration]]：Ollama bge-m3 和 DashScope text-embedding-v4 的向量混在一起算余弦相似度毫无意义）。因为"距离有意义"不是向量本身的属性，是"同一个坐标系"这个前提给的。
2. **查询必须过同一个 f**——查询不是拿原文去库里匹配，而是映射到同一个语义空间后，在这个空间里做近邻搜索（[[hnsw-index]] 的 ANN）。这就是"先 embedding 再算距离"。

## 4. 本质一句话

> Embedding 是一次**度量的重新定义**：把"语义相似"这个在原始空间里无法计算的概念，变成新坐标系里一次普通的距离计算。后续所有检索、聚类、推荐，本质都是在这个新空间里做几何运算。

这和激活函数（[[activation-loss-functions]]）是同一个思想的两面：激活函数在层与层之间重排表征（让网络能表达复杂函数），embedding 在输入端重排表征（让"相似"变成可计算）——**深度学习的核心操作就是不断构造"让下游任务变简单"的表征空间**。

补充：SurrealDB HNSW 索引定义里 `DIST COSINE` 用余弦而不是欧氏距离，因为文本向量归一化后余弦只看方向（语义取向）不看模长（信息量），是语义空间里更贴切的"距离"定义。
