# CAP 定理

分布式系统设计中最核心的基础理论。指出在分布式系统中，不可能同时完美满足以下三个特性，最多只能较好地满足两个。

## CAP 三要素

### C - 一致性 (Consistency)

所有节点在同一时刻都能看到相同的数据。每次写入操作后，所有后续的读取都能读到最新的值。

### A - 可用性 (Availability)

每一个非故障节点收到的请求都必须得到响应。哪怕系统部分出错，也保证能返回结果，但不能保证数据最新。

### P - 分区容错性 (Partition tolerance)

当网络发生故障或丢包时，系统仍能继续运行。分布式系统多节点必然通过网络连接，这也是系统的基本前提。

## 为什么不能三者兼得

在分布式系统中，网络故障（P）是必然会发生的。当网络断开时，系统必须在 C 和 A 之间做二选一的抉择：

- **若选择一致性（C）**：为了防止用户读到旧数据，断开连接的节点必须拒绝服务，这就破坏了可用性（A）
- **若选择可用性（A）**：为了保证所有节点都能正常响应，就必须允许节点继续服务，但这会导致数据不同步，破坏了一致性（C）

## 实际应用

| 系统 | CAP 选择 | 说明 |
|------|---------|------|
| [[oss]] | AP | 可用性优先，最终一致性 |
| 传统 RDBMS | CA | 一致性和可用性，单节点无分区 |
| Redis Cluster | AP | 可用性优先，最终一致性 |
| ZooKeeper | CP | 一致性优先，网络分区时部分节点不可用 |
