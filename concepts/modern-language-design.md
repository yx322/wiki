# 现代编程语言设计

**核心观点**：现代语言设计的"简洁"不是字符数最少，而是阅读时的认知负担最低。四个层面递进支撑，背后有一个统摄规律——**复杂度守恒**。

## 四层递进

### 一、语法：降低认知噪声

| 设计选择 | 原因 |
|----------|------|
| **显式 `let`** | 消除歧义推断：`let x = 1` 一眼是变量绑定，Python 的 `x = 1` 在不同上下文可能是赋值、重绑定、属性设置 |
| **类型后置** `name: Type` | 自动推导友好：编译器从右值推导类型，阅读顺序与推导顺序一致 |
| **大括号分隔** | 词法边界稳定：C 系 `if (cond) stmt` 省略大括号制造 bug（Apple goto fall）|
| **共享 DNA** | SurQL、Nushell、Moonbit、Rust 共享：显式绑定 + 类型后置 + 错误即值 |

**帕累托改进**：用微小的输入代价（多一个关键字、多一对大括号）换取系统性的简化。C 系的"省略"不是帕累托改进，是取巧。

**反面：样板代码不是简洁**。Go 的 `if err != nil`、Java 的 getter/setter——把重复体力劳动当作"简洁"。样板代码制造"虚假充实感"，把人按在流水线上当打字员。

### 二、语义：数据流动的形态

**表达式导向：一切皆值**。`if`/`match`/`for` 不是跳转指令，是值的生产者。后果是没有"无值的代码"——每一行都在产出数据。

**不可变默认**：`let` 不可变、`mut` 显式 opt-in。每个操作是纯粹的输入→输出变换，别名安全，推理成本恒定。

**管道化**：无副作用的条件下，每个操作都是纯粹的变换，自然可以串联。`input |> parse |> validate` 从左向右读，和数据实际流向一致。

**控制流即数据**：`Result<T, E>` 把"可能失败"编码进类型，`?` 运算符是管道化的错误传播。异常机制的问题是**隐式控制流**——读代码时看到 `foo()` 以为它只是调用，但可能在任意深度抛出。

### 三、类型系统：防线前移

**核心规律：约束越多，代码越少。** 类型系统每多一条约束，编译器就多替你验证一条路径，开发者就少写一份防御性检查。

**Parse, Don't Validate**：在边界处解析，在内部使用类型。parse 产生新类型（`VerifiedUser`），类型系统自动追踪"这个值是否已验证"。validate 是布尔检查，不改变类型——100 行之后编译器不知道这个字符串已经被验证过了。

**代数数据类型（ADT）**：Rust 的 `enum` 是 tagged union，`match` 要求穷尽性——漏掉一个变体就编译失败。C/Java 的 enum 只是命名常量，未处理的 case 在运行时静默跳过。

**无 null**：`Option<T>` 把"缺失"从隐式运行时炸弹变成显式类型约束。空引用是 Tony Hoare 的"十亿美元错误"。

**参数化多态**：泛型+自动推导 = 声明式逻辑编程。Zig 的 comptime 是反面教材——用命令式 if/for 做本该由逻辑推导完成的工作，意图丧失+报错灾难。

**类型系统是语义闭环**：ADT → match 穷尽 → Option 取代 null → 环内三条是结构性失效，缺任何一个，其余保证同时失效。

### 四、抽象设施：匹配软件的真实拓扑

**树在代码复用中崩塌的三重根因**：
1. **单轴分类**：业务维度一多，立即出现菱形灾难
2. **复用粒度不精确**：继承的复用单元是整个类，不能只继承一个方法
3. **状态污染**：父类字段对子类可见，破坏封装

**树 vs 标签**：class 继承是**树**（边只跨级连接，单父链收敛到根）；trait 是**标签**（一物多标签，自由组合，组合数量是标签种类的乘积）。

**语言设施谱系**：

| 语言 | 组合设施 | 继承设施 | 树形路径是否可达 |
|------|---------|---------|----------------|
| Java/C# | interface + 委托 | abstract class | ✅ 默认路径 |
| Scala/Swift | trait/protocol | class | ✅ 但 trait 优先 |
| **Rust** | **trait** | **无 class** | **❌ 路径切断** |

**机制极简 vs 策略极简**：
- **机制极简**（Lua）：提供正交原语，用户自行组合。"我相信你是聪明的，只给砖。"
- **策略极简**（Go）：连原语都不给，替用户做所有决策。"我假设你是愚蠢的，没收所有工具。"

## 统摄规律：复杂度守恒

**静态语义的验证需求不会凭空消失，只会转移**——编译器收编还是开发者手写。

| 层面 | 编译器收编 | 开发者手写 |
|------|-----------|-----------|
| 语法 | `let` 消除歧义 | 每处赋值靠上下文猜意图 |
| 语义 | 表达式化消除数据搬运 | 临时变量+赋值中转 |
| 类型 | trait 约束自动求解 | comptime if 逐条手写 |
| 错误 | `Result` + `?` 管道化 | `if err != nil` 逐行检查（可漏）|
| 复用 | trait 标签化组合 | 继承树形+委托字段样板 |
| 空值 | `Option` 编译器强制 | null 检查靠纪律 |

**复杂性债务的终局**："简单"语言靠生态空窗期红利存活，在生态成熟后被一次性结清——以样板代码、运行时事故、生态碎片化的形式偿还。
