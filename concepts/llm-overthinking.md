# LLM 过度思考批判

面向 Benchmark 的深度推理优化与真实软件工程需求存在根本性错配——**跑分越高，干活越差**。

## 核心悖论：草稿本的双重人格

`<think>` 标签是给模型一个"草稿本"：在吐出正式答案前，先在内部犯错、划掉、重来。这不是"深度思考"，而是**用额外的 token 消耗换取概率链条的自我修正**。

**但在厚 Harness 环境中，外部 Harness 本身就是终极草稿本。**

LSP、编译器（`cargo check`）、测试运行器是 100% 确定性的真实物理评估引擎。推理模型在 `<think>` 里花 30 秒模拟编译器，纯属无用功——真实编译器 10ms 内给出最精准答案。

### 厚 Harness 不需要深度 CoT 的三个理由

1. **外置纠偏等价于脑内推演**：IDE 和 Agent 框架具备"读取代码→报错标红→运行测试→反馈修复"的完整物理闭环
2. **过度思考摧毁心流**：推理模型在长上下文污染下，极易触发无病呻吟的反思
3. **商业算力灾难**：低难度场景常规模型直觉准确率已 95%+，为 0.5% 提升让用户傻等数千隐藏思考 Token，ROI 严重过度

## 工程本质：广度试错，非深度推演

真实应用的系统复杂度，本质是"组件交互的广度"。排障并非单点逻辑的深度推演，而是在不同层级调用几十个工具完成的长链路试错。

**日常工程需要的是"广度串联、快、抗摩擦"，不需要过度思考。**

## Bench 优化的荒谬

| 云评测逻辑 | 工程实战逻辑 |
|-----------|-------------|
| 思考时间越长 = 模型越聪明 | 思考时间越长 = 首字延迟越高 = 心流断裂 |
| API 单价越贵 = 效果越好 | 单价越贵 = Token 账单失控 = ROI 崩溃 |
| 榜单分数 T0 = 生产环境 T0 | 榜单用奥数题测，生产用高频工具调用测 |

## 模型实测四象限

```
快且靠谱：MiMo-V2-Pro, GLM-5.1
快但翻车：Qwen3.7（非思考模式）
慢且废：Qwen3.7（思考模式）
靠谱但慢：Claude Opus
```

## 深度思考的真实生态位

1. **面向学生的"自动解题机器"** — 有标准答案的题目
2. **中阶研究员的"心理安慰剂"** — 结果往往错，但给人"已尽力"的感觉
3. **Bench 与公关的"特技舞台"** — 拿高分、发推特、向投资人证明

## 思考管理光谱

```
[ 纯执行流 ] ── [ 可控思维流 ] ── [ 深度推理流 ]
100% 直球输出    认知载荷动态短路    无止境脑内博弈
                    ↑
            窄思维链 (MiMo 2.5)
            约束在工具链拆解+边界检查
```
