# 涌现式 SKILL

技能不是预先规划的，而是从真实使用中**自己长出来**的。这是 [[skillforge]] 在 ADR-0008 中确立的技能系统演进方向，与传统 ACL 权限模型形成架构级对立。

## 核心观念：一切是一张网络

记忆和技能不是两套东西，是**同一张网里不同的点**。

- 你 = 一个节点
- 你的部门 = 一个节点
- "查购物车" = 一个技能节点
- "销售部门开通了购物车功能" = 它们之间的一条线

## 涌现 vs 传统

| 维度 | 传统方案 | 涌现式方案 |
|------|---------|-----------|
| 技能定义 | 人工规划、登记在册 | 使用中自己长出来 |
| 权限模型 | ACL（user × skill 对照表）| 图可达性（membership 边）|
| 规模行为 | 平方劣化 O(n²) | 亚线性摊薄 |
| 技能加载 | 全量注入 prompt | 按需检索 Top-N |
| 技能边界 | 固定 | 随使用 merge/split 演变 |
| 控制目标 | 资源单元（静态快照）| 拓扑关系（动态可达）|

## 规模性判据（第一判据）

**一切取舍的第一判据不是功能多寡，是规模行为。**

### 传统 ACL：平方劣化

```
维护成本 = O(用户 × 技能)
```

两个维度都在涨，是平方级劣化。大厂配专门的规则团队也堵不住漏洞——不是团队不行，是 O(n²) 的关系维护在规模上物理性撑不住。

### 涌现图：亚线性摊薄

```
加一个人 = 加一条 membership 边(O(1)) → 继承组织全部能力
加一个技能 = 连到想共享的 org(O(1)) → 铺给所有人
```

连接越多、共享越广、摊薄越大——规模越大越划算。

### 一句话判据

```
ACL   = pairwise 组合爆炸    → 越用越难、物理性碰壁
Graph = 结构化共享摊薄       → 越用越好、连越密越省
```

## 控制目标判据（第二判据）

ACL 隐含要求 object 是边界固定、可枚举的资源单元。但涌现式 skill 是一团使用数据的子图，边界会随真实使用 merge/split 演变。

**ACL 没有明确的控制目标**——它预设的"有明确边界的资源单元"在涌现架构里不存在。

图谱把控制目标换成**"从主体出发沿 membership/hierarchy 可达的子图"**——拓扑不要求 skill 有固定边界，永不钉死。

## 全量加载问题

当前 Hermes 全量加载所有 SKILL 简介注入每轮 prompt：

```
O(N) × 每轮 token 开销  ← N = skill 数量
```

ACL 过滤不是解——话语权越大的人拥有的技能越多，过滤后剩的反而越多。ACL 是"删减视图"，不是"按需产出"。

**正确的解**：按需检索，根据当前任务只加载最相关的 Top-N 技能简介。

## 型态分置

| 层 | 存储 | 特性 |
|---|------|------|
| **实例态** | tasks/task_items 表 | 快变量：高频写、生命周期短 |
| **型（模板/规律）** | 知识图谱 | 慢变量：低频更新、长期积累 |

task 节点持有对 KG 节点的引用，高 churn 的实例态不灌进写时重的图。
