# BM25 排序算法

Best Matching 25，概率信息检索模型。是 TF-IDF 的进化版，Elasticsearch 和 [[surrealdb]] 等主流引擎的全文检索底层主力。

## 本质：TF-IDF 的改良版

BM25 和 TF-IDF 一脉相承，都包含 TF（词频）和 IDF（逆文档频率）的核心思想，但 BM25 解决了 TF-IDF 的两个致命缺陷。

| 维度 | TF-IDF | BM25 |
|------|--------|------|
| **词频处理** | 线性增长（出现100次=100倍得分） | 饱和曲线（$k_1$ 控制天花板） |
| **长度处理** | 简单除以总词数或不处理 | 动态评估（$b$ + 平均文档长度） |
| **理论根基** | 启发式算法（凭经验拼凑） | 概率模型（基于二值独立模型推导） |
| **现状** | 已基本淘汰 | 主流引擎绝对主力 |

> **TF-IDF 是 BM25 的"基础骨架"，而 $k_1$ 和 $b$ 是 BM25 装上的"避震器"和"方向盘"。**

## 两个核心参数

### $k_1$ = 1.2：词频饱和度

控制一个词在文档中出现次数对得分的影响程度。

- **1.2（默认）**：保守平衡。出现 1~3 次得分明显上升，10 次以上迅速饱和。防止关键词堆砌作弊。
- **0**：完全忽略词频
- **2.0+**：词频高的文档得分飙升

### $b$ = 0.75：文档长度归一化

控制文档长度对得分的惩罚/奖励。取值 0~1。

- **0.75（默认）**：中等偏上惩罚长文档。短文档中出现的词更有价值（浓度更高）。
- **0**：完全不考虑文档长度
- **1.0**：完全按文档长度严格比例缩放

## 调优建议

| 场景 | $k_1$ | $b$ | 原因 |
|------|-------|-----|------|
| **默认** | 1.2 | 0.75 | 万金油配置 |
| **结合 [[ngram-analyzer]] 使用** | 0.5~0.8 | 保持 | N-gram 切分导致词频虚高，需更快饱和 |
| **搜索标题/短文本** | 保持 | 0.1~0.3 | 文档长度差不多，不需要长度惩罚 |
| **搜索长篇大论** | 保持 | 0.75~0.9 | 长文档天然包含更多词汇 |

## 与 N-gram 的关系

N-gram 和 BM25 是**上下游配合**关系：

```
文本 → [[ngram-analyzer]]（切词）→ 倒排索引 → BM25（打分排序）→ 结果排名
```

1. **N-gram 切词**：把 "apple" 切成 "app", "ppl", "ple"
2. **倒排索引**：记录哪些文档包含这些片段
3. **BM25 打分**：搜索时找到包含片段的文档，计算得分

## 在 SurrealDB 中的使用

```sql
-- 定义全文索引（使用 l3gram 分析器 + BM25 评分）
DEFINE INDEX idx ON goods FIELDS goods_name
    FULLTEXT ANALYZER l3gram BM25 HIGHLIGHTS CONCURRENTLY;

-- 查询时使用 search::score() 获取 BM25 分数
SELECT id, search::score(1) AS score
FROM goods
WHERE goods_name @1@ "安全帽"
ORDER BY score DESC;
```

BM25 分数通常与向量搜索分数通过 [[rrf-fusion]] 或 [[search-linear]] 融合。
